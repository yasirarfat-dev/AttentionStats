# Data models

**Status:** Logical schema accepted; SQL/Room implementation and migrations pending. Updated 2026-10-29.
**Responsibility:** Defines entities, invariants, time, provenance and schema evolution.
**Related specifications:** [Storage](STORAGE-AND-RETENTION.md), [Contracts](NATIVE-CONTRACTS.md), [Tracking](TRACKING-SPEC.md), [Backup](BACKUP-RESTORE.md).
**Unresolved feasibility:** F-03 and F-04 in [Decisions](DECISIONS.md); Room 3/SQLCipher and archive envelope selected for prototype qualification; entity serialization, schema/migrations and integration remain unimplemented.

The standalone [AS-006 fixture](../native/storage-qualification/README.md) has one artificial record table for encryption/build qualification only. It is excluded from the product build and is not an implementation or migration of these entities.

The separate [archive-envelope fixture](../native/archive-qualification/README.md) has public artificial manifest/entity/end bytes for crypto readback only. Its fields are not this schema, and its independent reader implements no history/JSON admission, migration or restore. Product encodings and bounds remain AS-009/AS-020 work.

## Entity catalog

ADR-044 advances the narrow native store to **schema 3**: `LiveOverlayConfiguration` adds non-null boolean `showIcons=true` and `allAppsToday=true`, with SQL defaults of 1 and an explicit preserving 2→3 auto-migration. Enabled state, source/consent/history rows, generation and keys are retained. Existing 1→2 migration composes through 3; no destructive fallback or item identity. Display-only preferences are native-owned because the counter works without JS. Global day/category projections query authoritative exposures in the same half-open local-day range across saved apps, while visits stay app-specific. These are derived read models, not extra durable counters. The next paragraph describes the original schema-2 introduction.

ADR-041 changes adapter ownership and a separately consented temporary diagnostic, with no Room schema/source-ID/bridge migration. Geometry and scan-local association slots never enter exposure rows or become durable content identity. Other apps and mixed-feed surfaces require explicit future catalog/metric/episode/consent evolution; existing viewer history keeps its meaning.

AS-043 introduces a narrow **local Room schema v2**, with retained versioned schemas under `android/app/schemas/com.attentionstats.storage.AttentionDatabase`: StoreMetadata, SourceConfiguration, LiveOverlayConfiguration, ConsentRecord, SurfaceEpisode, Exposure and CoverageInterval. It is not the complete catalog or a portable archive format. Source IDs are `reels.instagram`/`reels.facebook`; source enablement and persisted pause are independent of OS accessibility and HUD visibility. Metadata separates configuration revision from history revision. Exposures retain observed wall/elapsed times, zone/offset, detector/consent revisions, count kind/reason, category and per-episode ordinal, with a cascading episode foreign key. Category is one of reel/photo/post/ad/unclassified under ADR-034. The explicit 1→2 auto-migration adds the column with unclassified as the default, preserving old history without inventing old categories. No destructive fallback. No item content or target-page identity is persisted. Interrupted visits close with uncertain quality on reopen; transient dedup is discarded and the first uncertain returning page is withheld.

All IDs are locally generated opaque strings. No hardware/advertising identifier, contact, product account or remote user key is needed. Stable observation identity is distinct from any transient item identity used by a detector.

LiveSurfaceSnapshot is a **derived read model**, not a second durable counter. It projects a SurfaceEpisode, committed Exposure records, CoverageIntervals and day bounds from [Live overlay](LIVE-OVERLAY-SPEC.md); [Contracts](NATIVE-CONTRACTS.md) owns its shape. This visit is already part of today; midnight changes daily membership without closing a continuous visit. Generation/revision invalidation follows deletion/restore. Rendering or replayed callbacks never increments an independent value.

ADR-039 does not change schema v2 or retain target-content identity. Ordinal exposure history includes real return transitions, with same-page redraw/loop deduplication. It cannot reconstruct distinct Reels or repeat frequencies. Future identity-qualified breakdowns need explicit scope, provenance, unknown-identity coverage, consent/retention/deletion behavior and a reviewed migration; never backfill identities into old rows or sum distinct counts across periods.

## Time, evidence and precision

UTC epoch milliseconds are the transport/storage instant. Store event-time zone ID and offset when established, and use explicit selected view zone for calendar grouping. Elapsed realtime is valid only within the same boot epoch. Durations are nonnegative milliseconds, counts nonnegative integers; SQL 64-bit values crossing JS must be safely representable or encoded as decimal strings under a versioned contract.

`timeBasis` distinguishes `source_wall` from `observed_monotonic`; `timeProvenance` records how each optional zone/boot/elapsed field was established, including reconstructed uncertainty. Query receipt clocks and current zone are query metadata, not historical event-time facts. Do not infer old elapsed endpoints from current clock offset. Durable observation identity/occurrence ordinals need the shifted-window and multiplicity qualification in [Collection feasibility](COLLECTION-FEASIBILITY.md#observation-provenance); query-local indexes are insufficient. No Room schema or migration exists yet.

The AS-003 pure prototype's `Signature`/`Occurrence` and `Batch` are experimental values scoped by its injected source/installation/generation snapshot, not SourceEvent entities or a persisted schema. Local ordinals preserve maximum observed group multiplicity; overlap correspondence remains unresolved and decreases are flagged. A batch contains query completion/position without metric coverage. Do not copy these values into the durable contract as proven identity or complete coverage.

Its `PlanStep.Excluded` and `nextPlanningAtMs` describe proposal partitioning, not durable CoverageInterval records or processed-history cursors. `SliceRun` holds bounded in-memory pending work/attempts only; unresolved intervals remain explicit when density or retry limits stop a run. It neither persists job state nor authorizes advancing across an exclusion.

Experimental `RangeProgress` pins scope/request/revision and bounded disjoint `RangeReceipt.Queried`/`Excluded` values. Query receipts contain query completion time; exclusions contain only their reason. Their complement yields unresolved work, never metric coverage or one global processed position. Pure acceptance returns a candidate snapshot; test-only assignment couples it with facts/query health. Recovery reissues proposals from accepted receipts under the same scope, without restoring speculative retries; scope changes fail closed. These are not new entity catalog entries, an alternate store or a selected serialization format. Durable receipts, production correction policy, scope migration and crash/restart schema remain AS-009/AS-010 design work.

`beginCorrection` returns an experimental fresh `RangeProgress` after a completed same-scope pass: bounded tail window, prior revision plus one, no transferred receipts. It neither mutates facts/health nor persists a target/schedule. Revision continuity prevents old ticket reuse when windows repeat; installation must compare the previous scope/revision atomically. Scope-change tests explicitly use independently rebuilt consent ranges and fresh revisions, preserving old snapshots separately. They select no serialization, namespace migration, consent reconstruction or deletion algorithm. Correction observations retain the existing multiplicity uncertainty; a completed pass supplies no coverage or completeness claim.

Every measure identifies source observation IDs or a bounded query provenance descriptor, reducer/model version, configuration revision, coverage interval, and kind (observed/estimate/classification/prediction). A confidence class is not a measured probability. Unknown metrics use null and reasons. Synthetic example: `com.example.social` has a covered episode from 2026-10-20T10:00:00Z to 10:10:00Z, 600000 ms; an unknown period afterward has no inferred duration.

## Relationships and deletion

[Analytics](ANALYTICS-SPEC.md) and [Metric catalog](METRIC-CATALOG.md) own detailed metric semantics. Base counts/durations/bytes are nonnegative. An explicitly derived net interaction delta is signed and labelled, with matching source/coverage; never cast it to a nonnegative base count. Ratios retain numerator/denominator and undefined reasons. The pure Kotlin SummaryFact supports additive nonnegative bases only; signed/ratio views and these Room entities remain unimplemented.

RetainedSummaryFact becomes authoritative for its exact metric/dimension/time partition only after a validated compaction transaction removes the detailed representation. AggregateBucket stays a rebuildable cache over surviving detailed/retained facts. Queries choose one representation per partition; never add raw detail to its summary or overlap daily/monthly authority. The query layer must supply explicit unknown partitions for missing eligible history; the calculation helper cannot infer them.

Source events may produce sessions, surface episodes and derived insights. Keep referential deletion rules explicit: deleting app/time/source history removes or clips intersecting episodes, content, notifications, aggregates and model state. Where an event supports a boundary outside the deletion range, rebuild affected sessions and remove evidence references that no longer exist. Do not leave titles or topic labels in cached explanations after deleting their source.

Rules are configuration, not history: selective history deletion retains rules unless the preview explicitly includes them. All-data reset removes configuration, consent, keys, jobs, tokens and UI preferences as well as history. Consent audit retained after a selective deletion contains only minimal consent metadata, never deleted behavioral payloads; full reset removes it.

## Migrations and schema versioning

Summary-only deletion operates at retained resolution. For a date/app/topic request finer than retained dimensions, offer deleting the whole affected summary or cancellation; never prorate counts or claim exact redaction. Deletion removes summaries/caches/models and installs fences even when original observations are gone. Titles/URLs/input text cannot survive in summary explanations/provenance. Summary archives carry these same resolution/deletion limits.

Use monotonically increasing Room schema versions, committed exported schemas, explicit transactional migrations, and fixtures for every supported upgrade path. No destructive fallback migration for user history. Migration failure leaves the original store recoverable and collection paused. Test database/WAL handling, storage exhaustion and interruption before changing a release's schema.

Backup format version and database schema version are independent. Portable archives contain a documented logical representation and manifest, not an uncontrolled copy of an open SQLite database. Import validates schema and bounds, applies supported staged migrations, and rejects unsupported future versions without touching live data. Rebuildable aggregates may be omitted; provenance, consent scope and coverage cannot.

The [ADR-031 prototype envelope](CRYPTO-ARCHIVE-DESIGN.md#logical-payload-and-restore-validation) uses strict length-bounded JSON records inside authenticated streaming encryption. Signed-64-bit fields use canonical decimal strings with domain validation; counts/references must agree across manifest, rows and end record. Exact entity bodies are not yet selected. Local wrappers/aliases, grants, ingestion cursors, command replay state and provider credentials are never portable entities; historical consent is provenance only, with imported sources/rules inactive. Generation-key routing metadata lives in native no-backup storage and does not introduce a second history authority.

AS-048 expands the source catalog without a schema change: existing schema-3 stores transactionally insert missing `reels.youtube`/`reels.tiktok` configuration rows disabled, unpaused and consent revision zero. Existing records retain their keys, generation, consent and counts. An existing-store catalog addition increments configuration revision once; reopening an up-to-date catalog is idempotent.

ADR-049 TikTok reducer page values are temporary content-change ordinals and are not stored. Saved Exposure.ordinal enumerates committed encounters within the visit for every source. No raw text, digest, durable content identity or backward-direction guarantee is added to history. Existing source rows retain their original semantics.

ADR-050 lifetime history, immutable event/origin provenance, future merge/deletion semantics and rebuildable calendar summaries are defined in [Storage and retention](STORAGE-AND-RETENTION.md#lifetime-event-history-and-future-multi-origin-merging). These are design obligations; current preview storage/aggregate/restore limits remain explicit.

The experimental Home-video increment reuses SurfaceEpisode.surfaceId: home_video records recognized inline encounters, while reels_viewer retains dedicated-viewer provenance. Episode closure separates route changes. Exposure/category totals retain the existing schema; no layout-node key is stored. The first scoped Home encounter and subsequent qualified transitions use the existing committed exposure path. No migration or historical reclassification is performed.
