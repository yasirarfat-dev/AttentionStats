# Capability matrix

**Status:** Authoritative expanded planned inventory; no end-to-end application capability implemented. Updated 2026-10-28.
**Responsibility:** Maps every capability to source, access, controls, limitations, phase, evidence, and an acceptance scenario.
**Related specifications:** [Tracking](TRACKING-SPEC.md), [Social](SOCIAL-MEDIA-SPEC.md), [Protection](PROTECTION-SPEC.md), [Tests](TESTING.md), [Tracker](FEATURE-TRACKER.md).
**Unresolved feasibility:** F-01–F-10 in [Decisions](DECISIONS.md). Public API availability is not device verification.

## Interpretation

ADR-041 isolates the current Instagram adapter from Android acquisition/lifecycle and shared counting/storage/UI, with enforced package boundaries and broader social-app scope including Reddit. The preview's two-source catalog/bridge remains narrow. A revised optional geometry diagnostic supports further Home-feed qualification, without enabling feed counts or admitting another platform/metric. C-06/C-07/C-33 remain experimental; see [adapter guide](SOCIAL-ADAPTERS.md).

The subsequent optional diagnostic association revision adds window/consent-fenced event sequence brackets, relative timing and safe source bounds. This is qualification tooling only; stable brackets do not qualify post identity or atomic source snapshots. No additional capability is admitted.

AS-043 integrates experimental native encrypted storage, source/privacy controls, metadata-only adapter infrastructure and an optional HUD into the main React Native Android preview. ADR-034 adds a version-pinned Instagram viewer-page candidate and separate layout/ad/unclassified categories, gated by updated disclosure consent; Facebook counting remains unavailable. This is a narrow implementation slice, not admission of complete C-06/C-07/C-23/C-24/C-30/C-32 or the stricter short-video metric. No working two-app counter or full-MVP status follows from a build, synthetic storage check or navigation screenshot. See [current integrated priority](STATE.md#implemented-100).

M = MVP, E = expansion, C = continuous evolution. Planned = specified; experimental = requires a feasibility prototype; blocked = cannot advance until the named gate clears; implemented = code and acceptance evidence exist. No row is currently implemented. No end-to-end row below has admitted device qualification. The scaffold has separate bootstrap/navigation phone/emulator checks; these do not qualify collection, storage, protection or the full C-23/C-30 capability. Registry/policy research does not change runtime status.

AS-002's [initial probes](DEPENDENCIES.md#as-002-isolated-compatibility-probes) and the experimental AS-004 scaffold do not qualify runtime rows. The scaffold's disabled-state routes, read-only bootstrap handshake and 37 packaged synthetic calculation checks on a physical phone are engineering evidence, not accepted C-23/C-30 functionality; F-03 and X-10 still govern acceptance.

[AS-003 public API review](COLLECTION-FEASIBILITY.md) adds staged source/lifecycle qualification, with no runtime admission. Historical screen/keyguard support starts at API 28; C-03/C-04 must expose unavailable fields on earlier APIs unless an independent live source is qualified. Query freshness alone cannot establish C-01–C-04 coverage or C-23 health. F-02/F-09 remain open.

The self-package timing/cancellation extension compiles and passes app lint and 15 host runner-safety tests. Updated execution on the physical API-36 phone passes both synthetic lifecycle pairs, validated query/iteration aggregates and all three injected cancellation boundaries, with instrumentation `-1` and temporary test package cleanup. [Measurements and limits](COLLECTION-FEASIBILITY.md#self-package-timing-and-cancellation-protocol) add no capability admission, OS allocation bound, cross-thread cancellation-latency or blocking-call interruption guarantee.

The separate AS-003 JVM reconciliation experiment tests bounded slices, multiplicity uncertainty, simulated consent/revision races, consent/fence planning, bounded density/backoff, per-range receipt recovery and completed-pass correction proposals. Its 129 checks distinguish queried/excluded intervals, preserve unresolved work and refuse stale scope/revision proposals at a simulated atomic boundary. Fresh overlap passes carry no receipts and increment revision; changed-scope fixtures require independently rebuilt effective consent without receipt migration. Planning positions, query completion and exclusion receipts never mean processed history or metric coverage. Durable progress, scope migration and production correction policy remain unresolved. It is excluded from application dependencies and establishes no C-01–C-04/C-23 runtime support, durable identity or complete coverage. The existing self-package phone result remains source-mechanics evidence only.

Access codes: U = user-granted Android Usage Access; A = separately disclosed and user-enabled Accessibility Service; N = Notification Listener access; P = notification posting permission where required; O = special overlay access if the chosen renderer needs it; S = system document-picker URI grant; D = notification policy access for optional DND; G = future provider authorization, blocked. “Local” means no Android grant beyond normal application storage. See [Permissions](PERMISSIONS.md) for declarations and grant types.

Individual data points, including short-video time/counts, post/story/ad exposure estimates, action evidence, byte statistics and summary tiers, are enumerated in [Metric catalog](METRIC-CATALOG.md). Source/control/limit/scenario definitions there complement these capability families. “Maximum detail” remains a user-selected, disclosed supported subset; [Analytics](ANALYTICS-SPEC.md) owns accounting semantics.

Control codes specify minimum controls, not optional refinements: T = off by default, source/app/category inclusion, exclusions, detail, pause, retention and delete; H = T plus separate supported-title/URL consent; R = disabled until explicit activation, per-rule behavior, targets, schedule, exceptions, override and emergency access; V = editable display/output controls and data-scope awareness; B = opt-in destination, scope, credentials, status, cancellation and deletion guidance. Exclusions apply before persistence. iOS is unimplemented for every row; it must report unsupported until a separate adapter proves availability.

## Admission procedure

Add new rows before implementation, including an acceptance ID in [Testing](TESTING.md) and a task mapping in [Feature tracker](FEATURE-TRACKER.md). A supported detector record must include application version range, Android build/API, locale, surface, evidence fields, fixtures, precision/recall procedure, known exclusions, and date. Do not publish real account traces. Changed versions invalidate untested claims; unsupported versions return unknown rather than using a generic scroll counter.
