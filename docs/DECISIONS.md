## HUD and encounter clarification — ADR-052 / 2026-10-29

User explicitly distinguishes temporary HUD hiding, persistent display settings and pausing collection. HUD Hide lasts until departure from the current app while observations continue; only app display settings persistently turn the counter off. Pause counting remains a separate action until resumed. The user also requests compact HUD access to auto-scroll, with no first-use explanations in the HUD. ## Version-independent detection, interventions and MVP 1.0 — ADR-066 / 2026-10-30

**Context.** Exact-version detectors stopped counting whenever a source app updated (Instagram 452 → 453 on the maintainer's own phone), counted only a few entry routes, missed first items and could not support other phones. The maintainer requires counting on every route into short videos, on any phone, plus Snapchat, stronger breaks/blocks and a publishable MVP today, and authorizes reading on-screen labels in memory (ADR-049 generalized).

**Decision.** Supersede ADR-046/049/065 detector pinning and per-app notices 3/4/5 with **notice 6**: one disclosure covering all five sources. Detection lives in the pure JVM `reels-core` module as per-app adapters that prefer stable view IDs and fall back to shared geometry (full-screen vertical pager + contiguous right action rail; feed media with a sound toggle). Item identity is a salted in-memory fingerprint of normalized on-screen metadata; raw labels are never stored.
