# Verification and acceptance

**Status:** Host and scoped physical Android checks available; full native/lifecycle/accessibility/release matrix remains incomplete. Updated 2026-11-15.
**Responsibility:** Owns acceptance scenarios, evidence quality and release gates.
**Related specifications:** [Capabilities](CAPABILITY-MATRIX.md), [Tracking](TRACKING-SPEC.md), [Protection](PROTECTION-SPEC.md), [Backup](BACKUP-RESTORE.md), [Security](SECURITY.md).
**Unresolved feasibility:** F-01–F-10 in [Decisions](DECISIONS.md); source/API/OEM support is not verified by calculation tests alone.

## Verification levels

Documentation: `python tools/check_docs.py` and `git diff --check`, plus human review of contradictions, public safety and source accuracy. Native unit tests: deterministic reducers/rules with injected time and minimized synthetic events. Persistence tests: transactions, dedup, migration, key loss and interruption. Contract tests: typed schemas, revisions, pagination, cancellations and dropped notifications. UI tests: partial grants, unknown gaps, accessibility and recovery. Device tests: source fidelity, reboot/OEM restrictions, overlays, background work and egress.

Each application evidence record needs commit/build, exact dependency/toolchain versions, Android API/build/OEM, target app/version/locale where relevant, fixture ID, expected/actual outcome, limitations and date. Public reports contain synthetic identifiers and aggregate outcomes only; no device identifiers, real accounts or usage traces. “Implemented” requires code plus passing relevant scenarios, not a written plan or mock screenshot.

### Logical archive page-capacity failure — 15/11/26

`archiveCapacity=true` runs production SQLCipher/Room and `LogicalArchive` against unique synthetic no-backup stores/Keystore aliases. Give source 256 exposures and each separate destination one different exposure. On the same confined writer as the nested operation, read `page_count`, set `max_page_count` to it and require its returned value. Run logical staging and caller-transaction replacement separately. Require a SQLite FULL diagnostic/type and callbacks proving archive execution, not an unrelated exception. Compare canonical rows from every application table (including provenance/local metadata) immediately and after reopening. Raise the writer cap to 4096 pages and retry each operation; require the independently staged incoming rows, then full committed-snapshot equality after reopening. Source/staging remain unchanged.

This uses the engine's real growth refusal without filling shared phone storage. It does not exercise filesystem ENOSPC, exhausted WAL/temp volume, provider writes, preflight reserves, process kill/power loss, coordinator error mapping/UI delivery or every durable boundary. [SQLite page-cap semantics](https://www.sqlite.org/pragma.html#pragma_max_page_count) and [FULL result code](https://www.sqlite.org/rescode.html#full) checked 15/11/26; assert behavior on the actual production driver rather than inferring it from documentation. Finally wipe owned plaintext, close stores, remove owned keys/directories and assert absence; require named PASS and raw -1. [Scoped result](evidence/archive-capacity.json).

### Logical archive interruption matrix — 15/11/26

`archiveInterruption=true` on `AnalyticsInstrumentation` exercises the production `LogicalArchive` and SQLCipher/Room store in unique no-backup directories with unique Keystore aliases. Source and destination contain different synthetic facts. Count the actual cancellation callbacks during a successful export, stage and transactional replacement, then inject a distinct `CancellationException` at every callback. Require that exact exception and callback number; unrelated failures cannot pass. After each cancellation compare every application table, including `FactOrigin` and `StoreMetadata`, both immediately and after closing/reopening the store. Compare canonical table rows rather than time-dependent exported manifest bytes.

Also inject failure after replacement returns but before the outer transaction commits, and a separate observer failure after commit returns. The first must preserve the original destination; the second must preserve the imported rows through reopening with the destination's local metadata unchanged. Repeated low-level replacement must not add facts or change provenance. This does not qualify coordinator command replay, success/error UI delivery, arbitrary coroutine suspension, process kill, power loss, ENOSPC, Android transport, provider durability or fresh-install recovery. It tests every existing logical-record callback, not every instruction or durable-storage boundary. No live singleton, real history, transport or preferences are used; finally close stores, wipe owned plaintext, remove owned keys/directories and assert absence. Require the named PASS and raw instrumentation -1.
